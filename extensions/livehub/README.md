# LiveNotes 监听中心（spike）

一个用来**验证**的 Chrome 扩展：能不能同时抓 N 个标签页的音频、抓的时候本地会不会吵、
切到后台会不会断、10 路到底吃多少资源。

它不是最终产品，只回答四个问题。

## 装上

1. 打开 `chrome://extensions`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」→ 选 `extensions/livehub` 这个文件夹
4. 建议固定到工具栏（拼图图标 → 图钉），方便点

## 用

1. 打开 5~10 个直播间标签页，让它们都在播
2. **切到每一个标签页，点一次扩展图标**（Chrome 要求每个页面单独授权，这是安全设计）
3. 首次点击会自动打开「监听中心」页面，列出所有在抓的标签页

## 要看的四件事

| 看什么 | 怎么看 | 期望 |
|---|---|---|
| 能不能同时抓多路 | 面板里出现 N 行，块数一直在涨 | 5 路以上不报错 |
| 本地会不会吵 | 用耳朵听 | **完全没声音**（声音被扩展拿走了） |
| 切后台会不会断 | 切到别的标签页/最小化，看「最近一块」 | 一直是 1~2 秒内 |
| 吃多少资源 | `.	oolsspike_measure.ps1 -Minutes 10` | 记下 chrome 内存/CPU 峰值 |

## 可选：推给本地服务

勾选面板上的「推送到本地服务」，会为每一路建一个真实会话并把 PCM 推到
`http://127.0.0.1:8765/api/live/chunk`，和服务端现有链路完全一致。
注意：服务必须用 `python run.py` 起着，且监听 `127.0.0.1`。

## 已知限制（就是想验证的那些）

- 每个标签页必须**手动点一次**扩展图标（`activeTab` 限制）
- 标签页被关闭 / 页面跳转会中断那一路
- 扩展没有做断线重连，spike 故意保持简单
## 自检

    node extensions/livehub/selftest.mjs

按 offscreen 文档的**真实能力边界**（只有 `chrome.runtime`，没有 `chrome.storage` / `chrome.tabs`）
把 offscreen.js 跑一遍：加载、握手、开始采集、送块、停止、状态清理。

之前两次线上崩溃（`chrome.storage is undefined`、`Receiving end does not exist`）都能被它拦住。
