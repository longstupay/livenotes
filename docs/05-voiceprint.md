# 05 · 跨场次认人：声纹底库与人物档案

> 一句话：**把「这一场里的第几号声音」变成「现实里的某个人」，靠的是声纹 + 你手动点的那个名字。**

## 1. 它解决的问题

实时链路和 `recluster.py` 只能在**一场之内**回答「有几个人、谁在说」，
出来的标签是 `SPK_00 / 主播 / 嘉宾2`——出了这一场就作废。

真正的业务问题是：「**老王今天到底来没来？**」
这需要跨场次记住一个人的音色。`app/voiceprint.py` 做的就是这件事。

## 2. 一个必须先讲清的边界

系统里**没有**「先录一段音、建一个声纹库」的注册流程，也不需要。
直播间一天来几百上千人，给每个人建档既不可能也没意义：

- 1:N 开集识别里，库里每多一个人，误报就多一分。1000 人的库、1% 的单次误报率，
  意味着每次查询都有十来个人「长得像」，系统只能瞎选。
- 真正值得记住的只有**你关心的那几十个人**。

所以这里做的是「**关注名单检索**」：不回答「这是谁」，只回答「**这个人来没来**」。
上麦的人发完即弃，只有被你点过名的人才进库。

## 3. 注册：改名即注册

不需要额外操作。你在一场里把 `SPK_02` 改成「老王」的那一下，就是注册：

```
改名 → store.rename_speaker()  (verified=1)
     → live.note_rename() → voiceprint.enroll_speaker()
         ├─ 取这一簇的全部句子声纹
         ├─ 算鲁棒质心（剔掉离群句，防抢话污染）
         ├─ 挑最多 5 条彼此不像的原型（覆盖不同语气/工况）
         └─ 写 persons + person_emb
```

**位置标签会被挡掉**：`主播 / 嘉宾2 / 说话人1 / SPK_03` 不是人名——
不同场次的「嘉宾1」根本不是同一个人，当身份用会把底库污染成垃圾桶
（见 `voiceprint.is_generic_name`）。

**同名的两次标注 = 同一个人**，会合并；但如果声纹差得太多（< 0.45），
只建立身份关联、**不追加原型**。这是被真实数据教育出来的：
两个不同的人被同名合并后，那个人的原型覆盖了两个音色，之后每一场都能误命中 0.6 分。

## 4. 检索：比的是簇，不是句子

```
一场结束 → recluster.py 先分好人（SPK_00..）
        → voiceprint.match_session()
            ├─ 每个簇取鲁棒质心（要求 ≥3 句且 ≥5 秒）
            ├─ 和底库每个人比：取最像的两条原型求平均 = 裸余弦
            ├─ 减去「本场背景」= 这一簇与同场其它簇的平均相似度
            └─ 三重门槛 → auto / cand / 无
```

### 为什么要减背景

同一个直播间的设备、码率、BGM 会把所有人的向量一起往一个方向拉。实测跨场次
互不相同的两个人，裸余弦能到 0.5 以上；直接卡 0.45 必然全错。
减掉「这个房间的底色」之后，噪声分布明显收窄（中位从 +0.29 降到 -0.05）。

### 为什么要用簇

单句 1~2 秒的声纹方差极大——**同一簇内两句的中位余弦只有 0.59**，10% 的同人对
甚至低于 0.45。但一个人一场里平均说 23 句 / 83 秒，聚合之后误差按 1/√n 掉。

### 为什么不用最大值

原型条数多的人天然占便宜（8 条里总有一条撞上）。实测会让常驻主播把每一场
都「吃」掉。改成**取最像的两条求平均**后，非本人的分数分布明显收窄。

## 5. 阈值是怎么来的

拿本项目真实库跑出来的（`python tools/calibrate_voiceprint.py`）：

| | 对数 | 得分中位 | p95 | p99 |
|---|---|---|---|---|
| 已知是本人 | 20 | **0.555** | — | — |
| 已知不是本人 | 176 | -0.054 | 0.144 | 0.223 |

于是：

| 门槛 | 值 | 作用 |
|---|---|---|
| `LIVENOTES_VP_AUTO` | 0.30 | 归一化分，落在非本人 p99 之上 |
| `LIVENOTES_VP_CAND` | 0.12 | 候选线，约 p95 |
| `LIVENOTES_VP_AUTO_MIN_RAW` | 0.55 | 裸余弦下限，挡掉「谁都不像」的场次 |
| `LIVENOTES_VP_AUTO_MIN_S` | 20 | 太短的簇一律只给「疑似」 |

三条同时满足才算 auto；只过 CAND 的进「疑似」，等你点一下。
**自动认定错了很伤人**——报错三次用户就不信这个功能了，所以宁可漏。

换设备、换场景、库里人变多之后，重跑一次校准脚本改环境变量即可，不用改代码。

## 6. 反馈闭环

界面上点「确认」不是只改个标签：

```
确认 → speakers.person_state=confirmed + 改 display_name
     → enroll_speaker(person_id=...)   把这一簇的原型补进底库
```

点「否决」则记 `rejected`，**复查时不会被同一个人再次命中**，
也不会污染底库。所以这个系统是越用越准的。

## 7. 页面

`/people`（主界面右上角「👤 人物」）：

- 左边是底库，按命中场次排序
- 右边是一个人在**哪些场次、哪一秒到哪一秒**出现过、得分多少
- 点「跳转」→ `/reader?session=X&t=123`，直接定位到那一刻播放
- 支持改名 / 合并（同名不同人）/ 从底库移除

## 8. 已知不行的地方

| 情况 | 结果 |
|---|---|
| 只说 3~5 秒就下麦 | 认不出。任何声纹系统都不行，代码里 `< 1.2s 不开簇` 已经承认这点 |
| 两个音色接近的同性别同龄人 | 会混，这是 CAM++ 的模型天花板 |
| 一簇里混了两个人（抢话/回音） | 质心被拉偏，鲁棒质心只能缓解不能根治 |
| 全场的簇彼此都很像（bg ≈ 0.8） | 分数被压平，会漏报。这是保守方向的错，可接受 |
| 同一个人被聚类拆成两簇 | 只保留分高的那一簇（一人一场只占一个座位） |

## 9. 相关文件

|---|---|
| `app/voiceprint.py` | 注册、打分、检索的全部逻辑 |

| `tools/selftest_voiceprint.py` | 不碰真库的行为自测（跑在副本上） |
