# 校对与术语：让逐字稿"能改、能搜、写得对"

两个内部使用最常遇到的痛点：

1. **ASR 一定会错**。FDE 听成"艾弗迪"、OPC 写成"O P C"、人名写成同音字。
   不能改，逐字稿就只是"能看"，不能当笔记用。
2. **聚簇一定会拆错**。两个人被分成三个簇、主持人和嘉宾偶尔串台。
   不能合并/改判，整场的时间轴就不可信。

## 一、术语表（/glossary）

存 data/glossary.json，按 mtime 缓存，**改完下一句 ASR 就生效**，不用重启。

三层规则，按顺序：

| 层 | 例子 | 说明 |
|---|---|---|
| 规范写法 | O P C / O-P-C / fde → OPC | 大小写、空格、点划都归一 |
| 别名替换 | 欧匹西 → OPC；FDI → FDE | 显式登记"听错的样子" |
| 模糊纠错 | FDE 被写成 FDl → FDE | 只对全大写 token 做，编辑距离 ≤1；普通词 for/the 不会被改 |

关注词会自动并进术语（只做规范写法，不猜别名）——少一个"还要去哪配"的心智负担。

**检索也吃这套**：搜「OPC政策」会拆成 OPC + 政策两条再合并结果；
搜别名「欧匹西」也能找到 OPC 的段落。

**补到旧稿**：术语页底部可以选"全部场次/某一场"跑一遍纠错。
人工校对过的句子会跳过（见下），不会被机器改回去。

边界：

- 别名别设得太短/太常见（比如把"阿哲"设成"阿哲老师"的别名，会改掉所有"阿哲"）；
- 纠错只作用于实时链路产出的文本和"补跑"的旧稿；导出、总结都是读库里的文本，
  所以补跑之后要重新生成总结/高光才会用新文本。

## 二、逐句校对（阅读页右上「✎ 校对」）

进入后按句列出：时间、说话人下拉、可编辑文本。

- **改字**：光标离开或 Ctrl+Enter 保存。保存会清空这句的 AI 指纹与特征，
  下次 AI 分析会重新标注（否则会出现"改了字但标签没变"的假象）。
- **改判说话人**：点说话人下拉换人；也可以「＋ 新建说话人」，等于把一个簇里的
  几句拆出去——这就是"拆分"的可用形态（真正的聚类拆分需要重新跑声纹，代价大且
  不一定更好）。
- **合并两个簇**：顶部「A 并到 B」。把误拆的"嘉宾2"并回"嘉宾"。
- **不会被重聚类覆盖**：改过的句子写 edited_at，重新分人会跳过它们。
  用户改过的东西，机器不要再改回去。

边界：

- 文本改动**不会**自动重算已生成的高光/总结；页面会提示"重新生成后生效"。
- 合并说话人不可撤销（要拆回去就逐句改判/新建）。
- 校对模式一次拉 5000 句；两小时以上的场次建议先筛选，再校对。

## 三、和推送的关系

- 卡片上的 👍/👎 落在 /card/feedback，写进 push_log 与 highlights；
- 学习只按特征标签（提到数字、结论句、抢麦…），不学具体句子；
- 台账 /pushes 能看到每条推送的结果和"没推的原因"。

## 四、验收

    python tools/push_preview.py            # 卡片 JSON（含 👍/👎 按钮）
    # 浏览器：
    /glossary                               # 加 OPC、别名 O P C，保存
    /reader?session=...                     # ✎ 校对：改一句、改判一句、合并一次
    /pushes?session=...                     # 看已发/未推/原因

数据库侧自检：

    SELECT id,text,edited_at FROM utterances WHERE session_id=? ORDER BY t_start LIMIT 5;
    SELECT item,status,reason FROM push_log WHERE session_id=? ORDER BY id DESC LIMIT 20;
