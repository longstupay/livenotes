## 怎么打开

直接双击 `workspace-b.html`，或在 Chrome 里打开：

```bash
"C:/Program Files/Google/Chrome/Application/chrome.exe" "C:/path/to/livenotes/docs/prototypes/workspace-b.html"
```

建议窗口 **1440×900 以上**。页面按 1500×940 设计。

### 直接进入某个状态

| 状态 | URL 参数 |
|---|---|
| 收听 · 信号画布（默认） | `?view=listen` |
| 收听 · 需要登录 | `?view=listen&room=ch3` |
| 收听 · 页面模式 | `?view=listen&room=ch1&stage=page` |
| 收听 · 添加直播间 | `?view=listen&add=1` |
| 收听 · 命令面板 | `?view=listen&palette=1` |
| 工作台 | `?view=workbench` |
| 文件中心 | `?view=files` |
| 人物档案 | `?view=people` |
| 设置 | `?view=settings` |

也可以组合，例如 `?view=workbench&panel=0` 收起右栏。

## 可以点什么

- **左栏**：收听 / 工作台 / 文件 / 人物 / 设置，整个壳不换窗口。
- **房间列表**：点击切房间；`↑` / `↓` 也可以切。
- **添加直播间**：点列表底部「＋ 添加直播间」，或 `Ctrl+L`；粘贴任意链接回车，会走「解析中 → 在听」的乐观状态。
- **静音**：房间头部或右栏 `M`；只静音扬声器，采集继续。
- **停止**：行内二次确认，不弹系统窗口。
- **显示页面 / 完成并收起**：演示「页面按需出现」，登录后回到信号画布。
- **命令面板**：`Ctrl+K`，支持输入过滤、`↑↓`、`Enter`。
- **实时字幕**：全部 / 高价值 / 关键词过滤。
- **工作台**：切场次、AI 总结四个维度、点时间码回溯（toast 演示）。
- **设置**：开关、下拉都只改演示状态。
- **顶栏「N 路在听」**：打开全局录制浮层，可静音 / 跳到房间 / 全部停止。

## 这个原型在验证什么

1. **单窗口**：没有任何主流程会开第二个窗口。
2. **对象优先**：左栏是房间/场次列表，不是功能页签。
3. **录音常驻**：顶栏「2 路在听」在工作台、文件、人物页都可见。
4. **按需页面**：默认信号画布；只有登录/验证时才显示直播页。
5. **行内反馈**：停止确认、直取失败、登录提示都在对象上，不用模态。
6. **一套语言**：深色信号语言 + 琥珀强调色，替代现在浅色工作台 + 深色收听页的拼接感。

## 边界（不要误读）

- **信号画布是 HTML 演示**。生产里同一个矩形是原生 WebView2 子视图；它不能圆角、不能盖 HTML，所以原型里的浮层（命令面板）在真实实现中需要先 `hide()` 舞台视图。方案文档 6.3 已写规则。
- **页面模式是假页面**，没有接抖音/视频号，也没有二维码登录。
- **所有数据是 mock**，添加房间只在前端插入一张卡，不会调用 `/api/rooms`。
- **深色是建议方向**，不是已锁定；交互模型与主题可以分开评审。
- **动画只用于表达状态**，不代表最终动效规格。
