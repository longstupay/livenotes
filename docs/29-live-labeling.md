---

## 0. 结论先行

标注不是新页面，而是**收听页的第三个舞台模式**：

```
舞台： 信号 | 页面 | 标注
```

进入标注后，舞台左右分栏：

- **左栏**：当前直播间的原生 WebView2 画面（与「页面」模式同一个子视图，只占左栏矩形）；
- **右栏**：本场实时字幕，逐句带说话人 chip；
- **右侧检查器**：本场声音、标注进度、这一路信号状态。

这样做的原因不是审美：WebView2 原生子视图永远盖在 HTML 之上，**任何 HTML 浮层都压不住它**。所以标注区不覆盖视频，而是和视频并排；只在 HTML 区域内的弹层（说话人改判、确认合并）才安全。窗口变窄时先压缩字幕行，再隐藏检查器，页面矩形始终以 `#annotPage` 的真实位置回报给 `room_open`。

---

## 1. 用户链路

1. 在「收听」选中一路直播，点舞台上的 **标注**；
2. 字幕持续滚动，主播先被自动认出，其余声音以 `SPK_02` 之类的簇号出现；
3. 右栏「本场声音」按说话时长排序，待认领的簇标黄；
4. 点字幕 chip 或声音卡片：
   - **起名 / 新建人物**：写入人物库并采集声纹；名字不是「主播 / 嘉宾 / 运营」这类角色词；
   - **只标角色**：只改本场标签，不写人物库、不采声纹；
   - **确认声纹候选**：把自动识别的「疑似 0.42」确认为本人；
   - **不是他**：本场拒绝该簇，自动认人不再打扰；
   - **并入某人**：整簇改判给另一个人（见 §4）；
   - **跳过**：本场本轮不再提示，只存在浏览器内存里。
5. 右侧进度实时显示 `已认领 / 全部声音`，状态栏和房间列表同步（`新声音 N`）；
6. 停止采集后仍可进入标注模式整理历史字幕，只是不再有原生页面和实时增量。

键盘：`M` 标记当前时刻，`Space` 暂停 / 继续，`Esc` 先关说话人弹层再退标注。输入框聚焦时快捷键不生效。

## 2. 状态语义

| 状态 | 来源 | 界面 | 是否算「已认领」 | 是否写人物库 |
|---|---|---|---|---|
| `confirmed` | 人工起名 / 确认候选 | 正常名字，绿色点 | 是 | 起名时是；确认候选复用已有声纹 |
| `cand` | 声纹候选 | `名字 疑似 0.42`，琥珀色 | 是（但标注为疑似） | 否 |
| `auto` | 连续命中后的自动认人 | 正常名字 | 是 | 否 |
| `unknown` | 新簇 | `SPK_02`，黄色点 | 否 | 否 |
| `rejected` | 人工「不是他」 | 划线，灰色 | 否 | 否 |
| 角色标签 | 只标角色 | `嘉宾`，灰蓝 chip，卡片注「仅角色」 | 是 | 否 |

**角色不是身份。** `主播 / 嘉宾 / 运营 / 说话人 / 未知 / SPK_n` 等通用词由后端 `GENERIC_NAMES` 和前端 `GENERIC_RE` 双重拦截：

- 前端不把角色词发给 `/api/persons/enroll`，改发 `/api/speakers/rename`；
- 即使绕过前端，`voiceprint.is_generic_name()` 也不会把角色词写进人物库。

进度条把角色算作「已认领」，但下方文案明确写「角色不算人物」，避免把 100% 误读成「本场每个人都进了人物库」。

## 3. 数据与接口

### 3.1 实时态

`GET /api/live/status?id=<room_id>`（现有）新增消费字段：

- `speakers[]`：`speaker_id / label / seconds / count / manual / person_state / person_name / person_score`；
- `partial`：当前未定稿的一句；
- `n_utterances / last_final_ago_s / last_chunk_ago_s / dropped / queued`。

字幕本身仍来自实时事件流（`S.lines`）；标注模式不额外拉 `/api/utterances`，避免实时与历史两套顺序打架。

### 3.2 已停止场次

- `GET /api/utterances?session_id=&limit=` 取字幕；
- `GET /api/speakers?session_id=` 取整场说话人合计（新增）。返回
  `speaker_label / person_state / person_name / verified / n / seconds`，按秒数倒序。
- 只有在选中场次变化时才拉一次 `/api/speakers`，轮询继续只拉增量字幕。

### 3.3 写入

| 动作 | 接口 | 说明 |
|---|---|---|
| 起名 / 新建人物 | `POST /api/persons/enroll` | 改名 + 声纹入库；返回 `{ok, added, reason}`，样本不足时前端如实提示「本次没入人物库」 |
| 只标角色 / 回退 | `POST /api/speakers/rename` | 只改本场标签 |
| 合并簇 | `POST /api/speakers/merge` | 库内合并 + 实时内存同步 |
| 不是他 | `POST /api/live/reject_hint` | 仅实时态；历史场次用 `speakers/rename` 回退 |
| 标记 / 暂停 | `POST /api/live/mark`、`/api/live/pause` | 沿用现有快捷键链路 |

## 4. 合并的边界

人工合并最容易出的问题是「刚并完，下一句又被分回原来的簇」。现在的处理分三层：

1. `store.merge_speakers()` 合并库内说话人与字幕；
2. `live.note_merge()` 立即改内存里的历史句、计数、标签、候选与拒绝状态；
3. `Clusters.fold(src, dst)` 把源簇 **退役**：
   - 源簇质心置空并加入 `retired`；
   - `assign()` / `order()` / `status()` 都跳过退役簇；
   - 目标簇接住源的质心（目标原本没有质心时），保证后续同一声音落到目标；
   - 簇号本身保留，避免新簇复用 `SPK_01` 造成历史引用错位。

两个都已有身份的簇合并时，前端先弹确认层：会说明「这一簇 N 句改判给谁、本场不再保留谁」。未知簇并进已认领簇则直接执行，不打断操作。

## 5. 已覆盖的边界

- **没有直播 / 没有场次**：右栏显示空态，不打开原生子视图；
- **窗口变窄**：<1280 压缩字幕行高、隐藏时长等次要列；<1080 隐藏右侧检查器，字幕占满右栏；
- **页面加载失败或没有 URL**：`#annotPage` 保留空态，字幕照常可用；
- **实时轮询**：标注模式下继续轮询；只有全屏「页面」模式暂停，避免和原生视图抢资源；
- **弹层遮挡**：说话人弹层只向右 / 向下夹取，不向左翻，否则会被原生视图盖住；
- **新句插入**：弹层打开时冻结字幕重绘，关闭后一次性补上，避免点错行；
- **自动滚动**：用户上滚即暂停跟随，滚回底部恢复；右栏顶部有「自动滚动」开关；
- **下游一致性**：改名 / 合并后，字幕、说话人卡、房间徽标、进度条同一次刷新；总结、导出、回听读的是同一份库内标签；
- **声纹样本不足**：不谎报成功，提示「本次没入人物库」，但名字仍然生效。
