## 0. 结论先行

这次不是三个独立问题，而是同一个缺口：**产品只做了「开始」，没做「结束之后」**。

- 有场次列表，没有场次的生命周期管理（回收站入口藏在文件中心）；
- 有「停止」，没有「移除房间」，停止后的卡片永远留在「在听」；
- 播放器只看数据库里有没有 `audio_path`，不看文件是否真的还在；
- 演示数据在空库时静默生成，用户不知道它是假的；
- 桌面壳没有接管 WebView2 的右键菜单，所以右键露出「返回 / 刷新 / 另存为 / 打印 / 检查」。

**建议按下面的顺序闭环：**

1. **先定义清楚四个动作**：停止采集、移除房间、移入回收站、彻底删除。它们不是一件事。
2. **把「能不能播」变成后端状态**，前端只展示，不猜。
3. **停止自动生成演示数据**；已有演示/空/重复场次进入「体检」清单，预览后清理。
4. **禁止 WebView2 默认右键菜单**，换成应用自己的对象菜单（场次 / 房间 / 字幕行 / 输入框）。
5. 右键不是唯一入口：每个对象行 hover 时出现 `⋯`，与右键同一套菜单。

本轮 P0 只做 1–4 的最小闭环；清理中心和重复采集防护放 P1。

## 1. 现状诊断

### 1.1 数据从哪来

| 来源 | 代码位置 | 表现 |
|---|---|---|
| 空库自动塞演示场次 | `run.py:361` → `app/seed_demo.py` | `DEMO_20261104_2000`，2 小时、无音频 |
| 重复启动采集 | 采集页 / 重试链路 | 同标题、开始时间相差 1 秒的两场（见下） |
| 失败的采集 | `LIVE_20261111_035314` | 355 秒音频、0 条逐字稿 |
| 停止后的房间 | `data/rooms.json` | 4 路全部 `stopped`，仍留在「在听」 |

对桌面数据目录做了一次体检（2026-11-11）：

- 场次 9 条：6 条活跃、3 条已在回收站（含 `DEMO_20261104_2000`）。
- 活跃场次里：
  - `LIVE_20261111_013608` / `LIVE_20261111_013610`：同一房间，开始时间差 1 秒，重复；
  - `LIVE_20261111_141451` / `LIVE_20261111_141452`：同一房间，开始时间差 1 秒，重复；
  - `LIVE_20261111_035314`：355 秒、0 句，属于空采集；
  - `LIVE_20261111_170625`：1 分 25 秒、21 句，正常。
- 房间 4 路全部已停止；其中两路带 `ffmpeg 404` / 重连失败错误。

**结论：真正的「演示假数据」只有 `DEMO_` 前缀那一条，而且已经在回收站；现在看起来乱的是「重复采集 + 空采集 + 停止后不清理的房间」。** 不需要也不应该一键删掉用户所有历史。

### 1.2 为什么「点了不能播」

播放器当前逻辑（`app/web/js/index/player.js:51`）：

```js
const has = !!s.audio_path;   // 只看字段，不看文件
```

- 演示场次 `audio_path = null`：播放键被禁用，但原因只在底部一行小字里，用户感知是「点了没反应」。
- 文件被保留期清理后，`audio_path` 仍有值：播放键可点，实际请求 404 或解码失败。
- 点击场次行只切换工作台，不会开始播放；工作台 iframe 还会整页重载一次，进一步像「没反应」。
- 已停止的采集场次，`audio_path` 可能指向正在收尾的文件，前端没有「收尾中」状态。

补充：实际抽查 `LIVE_20261111_170625.m4a`，`ffprobe` 显示 AAC-LC / 16 kHz / 单声道 / 84.99 秒，
`GET /api/audio` 返回 `206 audio/mp4`，音频本身可播。**所以优先修「状态与反馈」，不是先怀疑编码链路。**

### 1.3 为什么删不掉

- 删除能力只在文件中心：`app/web/library.html` 已有回收站、还原、只删录音、彻底删除。
- 场次侧栏（`desktop/dist/shell.js` 的 `renderSidebar`）只有点击切换，没有删除入口。
- 收听页只有「停止 / 重试 / 显示页面 / 实时字幕」，没有「移除」。
  `app/web/js/rooms/actions.js` 其实已经有 `/api/rooms/remove` 和确认弹层，但新壳没有接。
- 没有批量清理「空场次 / 重复场次 / 演示数据」的入口。

### 1.4 为什么右键是网页的

- 主窗口是 WebView2，默认右键菜单没有被关闭。
- 壳页右键就会出现：返回、刷新、另存为、打印、检查。
- 「检查」来自 debug 构建；正式版也不应该出现。
- 这不是网页版特性，是桌面壳没有接管上下文菜单。

## 2. 设计目标与原则

**一句话目标：让每个对象都有明确的「下一步」，让每个状态都说真话。**

六条原则：

1. **不静默生成**：空库不再自动塞演示数据。
2. **不静默删除**：任何删除都先进回收站；彻底删除只在回收站里发生。
3. **四个动作分开**：停止 ≠ 移除 ≠ 移入回收站 ≠ 彻底删除。
4. **播放状态必须真实**：可播、无录音、文件丢失、收尾中，各有各的界面。
5. **对象菜单只出现在对象上**：场次行、房间行、字幕行、输入框；空白画布不弹菜单。
6. **右键不是唯一入口**：行 hover 出现 `⋯`，键盘/触控板用户也能发现。

非目标：

- 不重写采集、ASR、总结链路；
- 不强制迁移旧数据，只做「体检 + 可选清理」；
- 不把网页版改成桌面行为（网页版没有 `__LN_DESKTOP__`，继续用浏览器原生右键）。

---

## 3. 四个动作的语义

| 对象 | 停止 | 移除 | 移入回收站 | 彻底删除 |
|---|---|---|---|---|
| **房间（在听）** | 结束采集，录音正常收尾；卡片保留为「已停止」 | 从在听列表移除；已录场次保留 | — | — |
| **场次（工作台）** | — | — | 软删除，音频移到 `data/trash`，可还原 | 仅回收站内操作，删行 + 删文件 |
| **录音文件** | — | — | — | 文件中心「只删录音」，逐字稿保留 |

交互文案必须写清楚结果：

- 停止：「停止这一路？录音会正常收尾保存。」
- 移除：「从在听列表移除？已经录下的内容会保留，仍能在工作台找到。」
- 移入回收站：「移到回收站？可在文件中心还原。」
- 彻底删除：「彻底删除，不可恢复（含逐字稿与音频）。」

## 4. 数据生命周期设计

### 4.1 给场次加「来源 / 质量」标记

后端在 `GET /api/sessions` 与 `/api/library` 的返回值里补充字段（向后兼容）：

```json
{
  "audio_state": "ready | missing | none | live",
  "audio_seconds": 84.99,
  "is_demo": false,
  "quality": {
    "empty": false,
    "duplicate_of": "",
    "reason": ""
  }
}
```

判定规则：

- `is_demo`：`id` 以 `DEMO_` 开头，或 `source_mode == "demo"`。
- `audio_state`：
  - `live`：该场次仍在 `live.list_active()`；
  - `ready`：`audio_path` 非空、文件存在、大小 > 0（WAV 再校验头）；
  - `missing`：`audio_path` 非空但文件不存在；
  - `none`：没有 `audio_path`。
- `empty`：`duration_s <= 5`；或 `n_utterances == 0` 且 `duration_s < 60`。
  **只做标记，不自动删。**
- `duplicate_of`：同标题、`started_at` 相差 ≤ 120 秒的场次中，保留
  「被房间引用 / 时长更长 / 逐字稿更多」的那条，其余标记为重复。

### 4.2 不再自动生成演示数据

- `run.py` 去掉 `if not n: seed_demo.seed(conn)`；改为显式开关：
  `LIVENOTES_SEED_DEMO=1` 时仅在空库生成。
- 空状态加两个入口：
  - 主按钮：「开始第一次监听」→ 切到收听页并聚焦添加框；
  - 次按钮：「加载一场演示数据」→ 生成后带「演示」徽标，可随时删除。
- 已存在的 `DEMO_` 场次：列表显示「演示」标签；侧栏工具区出现
  「清理演示数据」入口。

### 4.3 清理中心（P1）

入口：工作台侧栏工具区「体检」/ 顶部提示条（检测到 N 条可清理）。

面板内容：

```
可清理的场次 4
────────────────────────────────────────
[ ] 演示数据          1 条    DEMO_20261104_2000
[ ] 重复场次          2 条    LIVE_...013608 / 013610
[ ] 空采集            1 条    LIVE_...035314（355s，0 句）
[ ] 录音文件丢失      0 条
────────────────────────────────────────
默认勾选：演示 / 重复 / 空采集
操作：[移到回收站]  [只删录音]  [稍后处理]
```

规则：

- 默认只勾选「演示、重复、空采集」；`录音文件丢失` 默认不勾选。
- 永远先预览、再执行；不自动清理。
- 执行后 toast：「已移入回收站 4 条 · 撤销」。
- 「撤销」调用 `/api/library/restore` 逐条还原。
- 批量操作复用现有 `/api/library/trash`、`/api/library/drop_audio`，不新增删除 API。

### 4.4 防重复采集（P1）

- `POST /api/live/start` 增加 `room_id`；若该房间已有活跃会话，直接返回已有会话，不新建。
- 采集页重试时复用 `room.session_id`，不重复 `start`。
- 房间停止后保留 `session_id`，重试沿用同一房间，不产生「同标题双胞胎」。
- 历史重复场次只通过清理中心处理，不自动合并（避免误删真实录音）。

## 5. 播放闭环设计

### 5.1 三种播放器状态

| `audio_state` | 播放键 | 场次行徽标 | 播放器提示 | 可执行动作 |
|---|---|---|---|---|
| `ready` | 可点 | 有录音 | 拖动进度条或点时间码定位 | 播放 / 定位 / 导出 |
| `none` | 禁用 | 仅文字 | 本场没有原始音频，只能按时间码看文字 | 删除本场 / 打开文件中心 |
| `missing` | 禁用 | 录音丢失 | 录音文件已被清理，逐字稿还在 | 删除本场 / 去文件中心 |
| `live` | 禁用（收尾后回放） | 录制中 | 这一场还在录制，停止后才能回放 | 实时字幕 / 停止 |

补充：

- 播放过程中触发 `error`：立即暂停，提示「文件损坏或格式不支持」，
  并保留时间码与逐字稿浏览。
- `none` / `missing` 时，进度条显示 `—`，不再用 `duration_s` 假装时长。
- 点击时间码、字幕行仍然可以定位（文字闭环不依赖音频）。

### 5.2 点击行为

- **单击场次行**：打开工作台（保持现在的行为），不自动播放。
- **行 hover 出现播放按钮**：打开工作台并请求从 0 播放；
  若 iframe 被自动播放策略拦截，则聚焦播放键并提示「点播放开始」，不假装已播放。
- **双击场次行**：等同 hover 播放按钮。
- 侧栏行 hover 同时出现 `⋯`，打开与右键相同的菜单。

### 5.3 工作台 iframe 不再整页重载（P1）

现在每次切换场次都重设 `iframe.src`，整页重建。建议：

- 首次加载后，切换场次通过 `postMessage({type:'livenotes:open-session', sid})`
  让工作台内部切场次；
- 只有跨页面（工作台 ↔ 文件中心 ↔ 人物）才换 iframe；
- 这能显著减少「点了没反应」的错觉。

## 6. 右键菜单与桌面化交互

### 6.1 总原则

- **禁止 WebView2 默认右键菜单**：`AreDefaultContextMenusEnabled = false`。
- **正式版关闭浏览器快捷键**：`AreBrowserAcceleratorKeysEnabled = false`
  （F5 / Ctrl+R / Ctrl+P / Ctrl+S 不再触发网页行为）；
  debug 构建保留 devtools（Ctrl+Shift+I），正式版不出现「检查」。
- **应用菜单用 HTML 渲染**，不用系统原生菜单：
  - 与现有深色/纸面主题共用 token；
  - 支持图标、快捷键、危险项、禁用态；
  - 壳页和引擎页可以复用同一套视觉和键盘行为。
- **菜单只在有意义的对象上出现**；空白画布不弹菜单。
- **行 hover 的 `⋯` 与右键同一套菜单**，右键只是快捷方式。

### 6.2 菜单规格

#### 场次行（工作台侧栏）

```
▶  打开工作台                    ↵
▶  从开头播放                    （audio_state != ready 时禁用）
──────────────────────────────
✎  重命名
⧉  复制场次 ID
⤓  导出 Markdown
──────────────────────────────
🗑  移到回收站…                  （危险色）
```

#### 房间行（收听侧栏 / 右侧检查器）

```
▶  打开实时字幕
▣  显示采集页面
⧉  复制直播链接
──────────────────────────────
↻  重试采集                      （failed / stopped 时可用）
■  停止采集                      （live 时可用）
──────────────────────────────
✕  移除这一路…                   （危险色；明确「场次保留」）
```

#### 字幕行（工作台 / 阅读页）

```
▶  从 00:12:34 开始播放
⧉  复制这句话
⧉  复制时间码
──────────────────────────────
✎  改说话人 ▸
★  标记为高价值
```

#### 输入框 / 可编辑区

```
剪切            Ctrl+X
复制            Ctrl+C
粘贴            Ctrl+V
────────────────
全选            Ctrl+A
```

#### 选中文本

```
复制
搜索这段文字（可选，P2）
```

### 6.3 菜单视觉与键盘

- 宽度 220–260px；行高 32px；圆角 8px；阴影与现有浮层一致。
- 深浅主题共用 CSS 变量，不在 JS 里写死颜色。
- 分隔线前后留 6px；危险项使用 `--red`，hover 才填充底色。
- 键盘：`↑` / `↓` 移动，`Enter` 执行，`Esc` 关闭；打开时首项聚焦。
- 点击外部、滚动、窗口失焦均关闭。
- 靠近窗口右下角时自动翻转，不超出可视区域。
- 打开动画 120ms，不做大幅位移。

### 6.4 技术落点

#### 桌面壳（Rust）

在创建主窗口 / 应用内浏览器窗口 / 实时字幕窗口后，统一调用：

```rust
#[cfg(windows)]
fn tame_webview(win: &tauri::WebviewWindow, debug: bool) {
    let _ = win.with_webview(move |pw| unsafe {
        if let Ok(core) = pw.controller().CoreWebView2() {
            if let Ok(s) = core.Settings() {
                let _ = s.SetAreDefaultContextMenusEnabled(false);
                // 正式版关掉浏览器快捷键；debug 保留，方便排查
                let _ = s.SetAreBrowserAcceleratorKeysEnabled(debug);
                let _ = s.SetAreDevToolsEnabled(debug);
            }
        }
    });
}
```

适用范围：`main`、`rooms`、`diag`、`live-*`。
**不适用**于抖音采集窗口（`browser-*`）：那是外部页面，保留浏览器行为，避免影响登录/复制。

同时保留兜底：壳页和引擎页在 `contextmenu` 事件里 `preventDefault()`，
防止某些 WebView2 版本仍弹出默认菜单。

#### 壳页（`desktop/dist/shell.js`）

- 新增 `#ctxMenu` 容器和 `initContextMenu()`；
- `#sideList` 上监听 `contextmenu`，按 `data-session` / `data-room` 生成菜单；
- 菜单项通过 `data-act` 分发到现有函数：
  `openWorkbench` / `playSession` / `renameSession` / `trashSession` /
  `switchView('live')` / `retryRoom` / `stopRoom` / `removeRoom`；
- 复用现有 `openModal()` 做危险操作确认，不新造弹层。

#### 引擎页（`app/web/js/desktop-menu.js`，新增）

- 只在 `window.__LN_DESKTOP__` 为真时启用；
- 提供 `attachContextMenu(target, items)` 和默认的输入框菜单；
- 工作台字幕行、阅读页时间码、文件中心列表按需接入；
- 网页版（直接浏览器打开）不加载或直接返回，不改变现有行为。

#### 删除接口

全部复用现有接口，不新增删除 API：

| 动作 | 接口 |
|---|---|
| 场次移入回收站 | `POST /api/library/trash` |
| 还原 | `POST /api/library/restore` |
| 只删录音 | `POST /api/library/drop_audio` |
| 彻底删除 | `POST /api/library/purge` |
| 移除房间 | `POST /api/rooms/remove` |
| 停止采集 | `POST /api/rooms/close` |
| 批量状态 | `GET /api/sessions`、`GET /api/library` |

新增的只有：

- `GET /api/sessions` 的 `audio_state` / `is_demo` / `quality` 字段；
- （P1）`POST /api/live/start` 的 `room_id` 幂等参数；
- （P1）`POST /api/sessions/cleanup/preview`，或前端基于 `quality` 字段本地计算。

## 7. 分期与验收

### P0（本轮，半天到一天）

1. 关闭 WebView2 默认右键菜单与正式版浏览器快捷键。
2. 壳页场次行 / 房间行右键菜单 + hover `⋯`。
3. 场次「移到回收站」、房间「移除」接入现有 API；危险操作二次确认。
4. 停止自动 seed；`DEMO_` 场次显示「演示」徽标。
5. `/api/sessions` 增加 `audio_state` / `is_demo`；播放器按状态禁用并解释。
6. 收听侧栏增加「清除已停止」入口（只移除房间，不删场次）。

**验收：**

- 右键场次行：不再出现「返回 / 刷新 / 另存为 / 打印 / 检查」，出现应用菜单。
- 场次「移到回收站」后从列表消失；文件中心回收站可见、可还原。
- 房间「移除」后从在听消失；对应场次仍在工作台。
- 演示场次和 0 秒场次：播放键禁用，提示原因，不再显示假时长。

- 空库启动：不自动出现演示场次；「加载演示数据」可手动触发。

## 8. 风险与兼容

| 风险 | 处理 |
|---|---|
| `with_webview` 在非 Windows 平台不可用 | `#[cfg(windows)]` 包裹；其他平台用 JS `contextmenu` 兜底 |
| 禁用浏览器快捷键影响输入法/复制粘贴 | 只关浏览器级快捷键；Ctrl+C/V/X/A 保留 |
| 自定义粘贴在 WebView2 权限受限 | P0 先保留 Ctrl+V；右键粘贴用 `navigator.clipboard`，失败时提示用快捷键 |
| `__LN_DESKTOP__` 未注入到 iframe | 用 WebView2 设置保证不出现浏览器菜单；iframe 菜单作为 P1，并先做注入验证 |
| 移入回收站后房间仍引用该场次 | 房间卡片保留，工作台显示「已移入回收站」；不自动改房间状态 |
| 删除正在采集的场次 | 禁止；先停止采集，再允许移入回收站 |
| 清理中心误删 | 默认只勾选演示/重复/空采集，先预览，执行后可撤销 |
| 去掉自动 seed 影响测试 | 测试显式调用 `seed_demo.seed()` 或设置 `LIVENOTES_SEED_DEMO=1` |

## 11. P1/P2 落地记录（2026-11-11）

P1/P2 全部按第 7 节完成，实现时定了几个边界：

- **清理中心是「候选 + 预览 + 撤销」**：`GET /api/cleanup` 只把演示、0 秒空采集、
  重复场次列为候选，正在采集的场次永远排除；前端默认勾选候选，执行走
  `POST /api/library/batch {action:'trash'}`，底部撤销条再批量还原。
- **防重复采集按 `room_id` 幂等**：`/api/live/start` 在锁内先查房间绑定且仍在
  采集的场次，命中就直接返回（`reused:true`），不再因为重试/刷新新建一场；
  新场次成功后回写 `rooms.session_id`。采集侧自动重连也带同一个 `room_id`。
- **工作台内切场次不再重载 iframe**：壳页对同一场只发 `ln-open-session`，
  工作台 `selectSession` 原地换数据并回执 `ln-session-changed`；只有切换到
  文件中心/人物/设置等其他页面时才换 iframe 地址。播放中的音频、筛选和滚动
  位置因此都能保住。
- **iframe 内菜单是应用内菜单**：`app/web/js/embed.js` 在嵌入模式提供输入框
  （剪切/复制/粘贴/全选）、选中文本（复制/全库搜索）、字幕行（定位/复制/
  改说话人/标记高价值/搜索）三套菜单；搜索面板直接显示在 iframe 里，因为
  桌面壳会隐藏页面顶栏，原先的全局搜索框在壳内不可见。
- **高价值标记是手动高光**：`highlights.kind='manual'` 绑定 `utterance_id`，
  重新生成自动高光时保留；字幕行和高光榜都能看到「高价值」标记。
- **批量与回收站入口**：工作台侧栏支持批量勾选、批量移到回收站、批量导出
  zip；文件中心新增「体检清理」页签，回收站可从侧栏一键进入。
